# IntellaFeeder v3 — what changed

*(Version française plus bas — [aller au français](#intellafeeder-v3--ce-qui-a-changé))*

Version 3 is an **interface release**. Nothing changed in what the tool writes:
the JSON descriptors, the task files and the resilient `.bat` are byte-for-byte
what v2.9 produced. What changed is everything around them — how the window is
organised, what it explains, and what it stops getting wrong.

It was released in four increments on 11 September 2026: **v3.0** (the rework
itself), **v3.1** (ergonomics after a day of real use), **v3.1a** (a pass done
screen by screen on screenshots) and **v3.1b** (translations).

---

## v3.0 — the rework

### A trail, not a row of tabs

Fourteen screens were mocked up in HTML, in three directions and four screen
sizes, from 13″ to 27″. The one chosen was **"Parcours"** (trail): the window
now shows **the job** — ① the case, ② import the sources — with the four
screens that are not part of the job (case detail, profiles, maintenance, help)
kept aside as **tools**.

Each step carries a **state** — to do / in progress / done — computed from real
progress. Without that, the trail would only be a tab bar in disguise.

Under the hood the `ttk.Notebook` is kept, simply stripped of its tabs
(`Headless.TNotebook`), so page switching, sub-tabs and the greying-out of a
compound case all keep working.

### Twelve decisions, taken on the mock-up

| Decision | Kept |
|---|---|
| Visual direction | **Trail** |
| Context bar replacing "common settings" | yes |
| Import parameters folded away | yes |
| "⋯" menu for rare actions | yes |
| Tick a whole task column from its header | yes |
| Task columns named (OCR/MD5 instead of T1/T2) | **no** — T1/T2 stay, real name in the tooltip |
| Already-indexed sources struck through rather than removed | yes |
| Profiles form in two columns | yes |
| Density and text-size setting | yes |
| Permanent status bar at the bottom | yes |
| Internal jargon removed from labels | yes |
| Log filters (All / Warnings / Errors) | yes |

### Density and text scale

Maintenance → Options: compact / normal / comfortable, plus a font scale from
80 % to 140 %, applied **without restarting** and remembered in the `.ini`. The
same window is meant to be usable on a laptop and on a large desk screen.

### Colour is a signal, not decoration

Four roles and nothing else: **green** = the action that advances the work (one
per panel), **red** = destructive or an anomaly, **orange** = something is still
to be done, **blue/purple** = a jump to another screen. Everything else is
neutral. v3 adds a fifth tint that is *not* a button role: a teal used for
chrome (current step, focus, selection), and a second button level — coloured
buttons are filled, neutral ones are outlined.

---

## v3.1 — ergonomics, after a day of use

- **Two steps, not three.** "Sources" and "Import" opened the same page.
- **Profiles: two sub-tabs, not three.** Four places used to talk about MIME
  types without talking to each other — a filter field, a two-pane popup, a
  category picker with checkboxes, and a reference sub-tab. Adding a type in the
  popup ticked nothing in the picker. They are now one screen, and the
  checkboxes are gone: a filter is composed by **adding entries** taken from the
  reference list.
- **Secondary windows can be minimised** (no `transient()` — on Windows it turns
  a window into a tool window, which loses its Minimize button).
- **The log filters by physical line, not by entry.** IntellaCmd's output
  arrives as one call to `log()` holding dozens of newlines: a search used to
  keep the whole block, fifty lines for one match. It looked like "search only
  works on warnings" — warnings happen to be single-line.
- **Help**: searchable with a hit counter, a capped reading width, and three
  **drawn** diagrams (the trail, include/exclude, a multi-segment image). Drawn,
  not screenshotted: a screenshot becomes wrong at the first UI touch-up.
- 🐞 **A saved profile silently lost its type filter.** Moving the "Filters"
  group out of the form removed the `sourceTypeFilter` key from the form's
  variables, so collecting the values no longer found it. Caught by
  `tests/manuel_construction.py`, not by pytest.
- **MIME reference: the contract was reversed.** An imported `.properties` file
  used to *replace* the built-in descriptions. It now **accumulates** —
  successive imports feed a single cumulative file, the newest wins collisions,
  and nothing already known is lost. You import to gain labels, not to lose
  them.

## v3.1a — the pass on screenshots

Six defects that only a screenshot shows:

- the footer of the reference pane was stacked *after* its table, so the buttons
  were pushed into the bottom-right corner and the counter was cut to "33 t";
- "Describe this type…" was greyed out with a read-only profile, although it
  acts on the reference list, not on the profile — and it has since been removed
  from that screen entirely: **a type is named in one place only**, Maintenance
  → MIME types;
- types with no label showed **their own name** as their description, so the
  "no description" filter filtered nothing;
- the help still had ~150-character lines;
- "⋯" read as "··" on screen;
- a filled green button set to `disabled` stayed bright green and looked active.

Plus two that were worse than cosmetic:

- 🐞 **"View the source settings…" opened empty.** A colour constant had gone
  away with the code being deleted, and two lines still called it: `NameError`
  right after the header, a 940×600 window with two lines in it and no error
  anywhere. Hence `tests/test_noms_definis.py` — an AST pass that fails as soon
  as a module cites a name nothing defines. `py_compile` never sees this, and
  pytest covers no widget.
- 🐞 **The cumulative MIME file was ordered by date.** Two files written within
  the same second share a timestamp, and the sort then fell back on their names
  — a just-recorded import could be overwritten by an older file. Intermittent
  by nature.

Also: double-click adds on the right and removes on the left, the filter mode's
**sentence** now carries the colour (red for exclude, green for include) instead
of its label, and three buttons were re-aligned.

---

## v3.1b — translations

- 🐞 **A translated label must never live in a class constant.** The MIME
  "comes from" column held its three labels in one, frozen in French when the
  module was imported — before a language was even chosen. It stayed French in
  the English UI.
- **The startup log was bilingual**: its first three lines were hard-coded
  French while the rest of the screen was English.
- **The `lang/` folder is optional, and the Files screen now says so.** It was
  shown as "missing" in orange, like a fault to repair — yet the languages are
  *built into* the executable and that folder only exists to *override* a
  translation without rebuilding. A new button seeds it with a copy of the
  built-in languages, and never overwrites a file already there.

**Known gap**: 11 log lines in `case_export.py` and `generator.py` are still
French. Those modules take a `log` callable and do not import the i18n layer by
design.

---

## Upgrading

Nothing to migrate. Profiles (`profils/*.json`), the settings file
(`intellafeeder.ini`) and the per-case cache (`IF_<case>.info`) are read as they
are. Two new `.ini` keys appear on first launch (`density`, `font_scale`).

If you keep a `lang/` folder next to the executable, its files still take
priority over the built-in languages — but they are from v2.9 and will lack the
v3 strings. Delete them (the built-in languages are complete), or reseed the
folder from Maintenance → Files.

# IntellaFeeder v3 — ce qui a changé

*(English version above — [go to English](#intellafeeder-v3--what-changed))*

La version 3 est une **version d'interface**. Rien n'a changé dans ce que
l'outil écrit : les descripteurs JSON, les fichiers de tâches et le `.bat`
résilient sont, à l'octet près, ceux que produisait la v2.9. Ce qui a changé,
c'est tout ce qu'il y a autour — l'organisation de la fenêtre, ce qu'elle
explique, et ce qu'elle cesse de dire de travers.

Elle est sortie en quatre temps le 11 septembre 2026 : **v3.0** (la refonte),
**v3.1** (ergonomie après une journée d'usage réel), **v3.1a** (une passe écran
par écran, sur captures) et **v3.1b** (traductions).

---

## v3.0 — la refonte

### Un parcours, pas une rangée d'onglets

Quatorze écrans ont été maquettés en HTML, en trois directions et quatre
tailles d'écran, du 13″ au 27″. La direction retenue est **« Parcours »** : la
fenêtre montre désormais **le travail** — ① le cas, ② importer les sources — et
range à côté, en **outils**, les quatre écrans qui n'en font pas partie (détail
du cas, profils, maintenance, aide).

Chaque étape porte un **état** — à faire / en cours / fait — calculé sur
l'avancement réel. Sans lui, le fil ne serait qu'une barre d'onglets déguisée.

Sous le capot, le `ttk.Notebook` est conservé, simplement privé de ses onglets
(`Headless.TNotebook`) : le changement de page, les sous-onglets et le grisage
d'un cas compound continuent de fonctionner tels quels.

### Douze décisions, arbitrées sur maquette

| Décision | Retenu |
|---|---|
| Direction visuelle | **Parcours** |
| Barre de contexte à la place des « paramètres communs » | oui |
| Paramètres de l'import repliés | oui |
| Menu « ⋯ » pour les actions rares | oui |
| Cocher une colonne de tâche entière par son en-tête | oui |
| Colonnes de tâches nommées (OCR/MD5 au lieu de T1/T2) | **non** — T1/T2 restent, nom réel en infobulle |
| Sources déjà indexées barrées plutôt que retirées | oui |
| Formulaire Profils sur deux colonnes | oui |
| Réglage de densité et de taille du texte | oui |
| Barre d'état permanente en bas | oui |
| Jargon interne retiré des libellés | oui |
| Filtres du journal (Tout / Alertes / Erreurs) | oui |

### Densité et échelle de texte

Maintenance → Options : compacte / normale / confortable, plus une échelle de
police de 80 % à 140 %, appliquées **sans redémarrer** et mémorisées au `.ini`.
La même fenêtre doit servir sur un portable comme sur un grand écran de bureau.

### La couleur est un signal, pas une décoration

Quatre rôles et rien d'autre : **vert** = l'action qui fait avancer le travail
(un seul par panneau), **rouge** = destructif ou anomalie, **orange** = il reste
quelque chose à faire, **bleu/violet** = renvoi vers un autre écran. Tout le
reste est neutre. La v3 ajoute une cinquième teinte qui n'est *pas* un rôle de
bouton : un teal réservé au chrome (étape courante, focus, sélection), et un
second niveau de bouton — coloré = plein, neutre = en contour.

---

## v3.1 — l'ergonomie, après une journée d'usage

- **Deux étapes, plus trois.** « Sources » et « Import » ouvraient la même page.
- **Profils : deux sous-onglets, plus trois.** Quatre endroits parlaient des
  types MIME sans se parler — un champ « filtre », un popup à deux panneaux, un
  sélecteur de catégories à cases à cocher, et un sous-onglet « référentiel ».
  Ajouter un type dans le popup ne cochait rien dans le sélecteur. Tout est
  réuni, et les cases à cocher disparaissent : on compose un filtre en
  **ajoutant** des entrées prises dans le référentiel.
- **Les fenêtres secondaires sont réductibles** (plus de `transient()` : sous
  Windows, il transforme une fenêtre en fenêtre outil, qui perd son bouton
  Réduire).
- **Le journal filtre par ligne physique, pas par entrée.** La sortie
  d'IntellaCmd arrive en un seul appel à `log()` contenant des dizaines de
  retours à la ligne : la recherche gardait le bloc entier, cinquante lignes
  pour une seule qui correspond. Cela se présentait comme « la recherche ne
  marche que sur les alertes » — les alertes sont mono-ligne.
- **Aide** : cherchable avec compteur de résultats, largeur de lecture
  plafonnée, et trois schémas **dessinés** (le parcours, include/exclude, une
  image multi-tronçons). Dessinés, pas photographiés : une capture d'écran
  devient fausse à la première retouche d'interface.
- 🐞 **Un profil enregistré perdait son filtre de types, en silence.** Sortir le
  groupe « Filtres » du formulaire avait retiré la clé `sourceTypeFilter` des
  variables du formulaire, que la collecte des valeurs ne trouvait donc plus.
  Attrapé par `tests/manuel_construction.py`, pas par pytest.
- **Référentiel MIME : contrat renversé.** Un `.properties` importé
  *remplaçait* les descriptions embarquées. Il **s'accumule** désormais : les
  imports successifs alimentent un fichier cumulatif unique, le plus récent
  gagne les collisions, et rien de ce qui était connu n'est perdu. On importe
  pour gagner des libellés, pas pour en perdre.

---

## v3.1a — la passe sur captures

Six défauts que seule une capture montre :

- le pied du panneau de référentiel était empilé *après* son tableau : ses
  boutons se retrouvaient dans le coin bas-droit et le compteur était coupé à
  « 33 t » ;
- « Décrire ce type… » était grisé avec un profil en lecture seule, alors qu'il
  agit sur le référentiel et non sur le profil — et il a depuis quitté cet écran
  pour de bon : **on nomme un type à un seul endroit**, Maintenance → Types
  MIME ;
- les types sans libellé affichaient **leur propre nom** en guise de
  description, si bien que le filtre « sans description » ne filtrait rien ;
- l'aide gardait des lignes de ~150 caractères ;
- « ⋯ » se lisait « ·· » à l'écran ;
- un bouton vert plein passé en `disabled` restait vert vif et paraissait actif.

Et deux qui étaient plus que cosmétiques :

- 🐞 **« Voir les réglages de la source… » s'ouvrait vide.** Une constante de
  couleurs était partie avec le code qu'on supprimait, et deux lignes
  l'appelaient encore : `NameError` juste après l'en-tête, une fenêtre de
  940×600 avec deux lignes dedans, et aucune erreur nulle part. D'où
  `tests/test_noms_definis.py` — une passe AST qui échoue dès qu'un module cite
  un nom que rien ne définit. `py_compile` ne voit jamais cela, et pytest ne
  couvre aucun widget.
- 🐞 **Le fichier MIME cumulatif était classé par date.** Deux fichiers écrits
  dans la même seconde portent la même date, et le tri retombait alors sur leur
  nom — un import tout juste enregistré pouvait être écrasé par un fichier plus
  ancien. Intermittent par nature.

Également : le double-clic ajoute à droite et retire à gauche, c'est la
**phrase** du mode de filtre qui porte la couleur (rouge pour exclude, vert pour
include) et non plus son intitulé, et trois boutons ont été réalignés.

---

## v3.1b — traductions

- 🐞 **Un libellé traduit ne se met jamais dans une constante de classe.** La
  colonne « Vient de » du référentiel MIME gardait ses trois libellés dans une
  seule, figée en français au chargement du module — avant même qu'une langue
  soit choisie. Elle restait française dans l'interface anglaise.
- **Le journal de démarrage était bilingue** : ses trois premières lignes
  étaient écrites en dur en français alors que le reste de l'écran passait en
  anglais.
- **Le dossier `lang/` est facultatif, et l'écran Fichiers le dit enfin.** Il
  s'affichait « absent » en orange, comme un manque à réparer — alors que les
  langues sont *embarquées* dans l'exécutable et que ce dossier ne sert qu'à
  *surcharger* une traduction sans reconstruire. Un nouveau bouton y dépose une
  copie des langues intégrées, et n'écrase jamais un fichier déjà présent.

**Limite connue** : 11 lignes de journal de `case_export.py` et `generator.py`
restent en français. Ces modules reçoivent une fonction `log` et n'importent pas
la couche i18n, par construction.

---

## Mise à jour

Rien à migrer. Les profils (`profils/*.json`), le fichier de réglages
(`intellafeeder.ini`) et le cache par cas (`IF_<cas>.info`) sont relus tels
quels. Deux nouvelles clés apparaissent au `.ini` au premier lancement
(`density`, `font_scale`).

Si vous gardez un dossier `lang/` à côté de l'exécutable, ses fichiers restent
prioritaires sur les langues embarquées — mais ils datent de la v2.9 et il leur
manquera les chaînes de la v3. Supprimez-les (les langues embarquées sont
complètes), ou régénérez le dossier depuis Maintenance → Fichiers.
